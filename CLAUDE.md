# Tixo — нотатки для ШІ-асистента

Платформа подій і квитків, курсовий проєкт «Web-технології». Go-моноліт: один бінарник `cmd/tixo`
з підкомандами (`serve`, `migrate`, `probe`, …).

## Правила коду

- **Жодних коментарів у коді**, ні в Go, ні в SQL, шаблонах, CSS, JS, YAML, TOML, Dockerfile, Makefile, `.env*`.
  Дозволено лише директиви: `//go:embed`, `//go:build`, анотації goose (`-- +goose …`) і sqlc
  (`-- name: …`), а також заголовки згенерованих файлів. Перевіряє тест `internal/repolint`. `//nolint` не
  використовуємо — виправляємо код.
- **Шари:** controller/handler → service → store (sqlc). Права доступу і тенант перевіряє сервіс.
- **Інтерфейс двомовний (uk/en).** Жодного тексту прямо в шаблоні: кожен рядок додається в обидва
  `web/locales/*.toml` у тій самій зміні. Застосунок не стартує, якщо ключі мов розходяться.
  `description`, `id`, `one`, `other` тощо — зарезервовані слова go-i18n, як ключі їх не використовувати.
- **Схема БД — тільки через міграції** в `internal/db/migrations`. `internal/db/gen/` генерує sqlc (`make gen`),
  руками не редагувати.
- **Конфіг — тільки через env** (`internal/config`). Нова змінна → `.env.example` + README.
- **Зовнішні ефекти** (Telegram, LLM, хмара) — за прапорцем dry-run/фейку, безпечним за замовчуванням.

## Перевірка

```sh
make check   # lint + sqlc diff + усі тести з postgres/redis/rabbitmq
make test    # швидко, без сервісів
```

Інтеграційні тести працюють лише з БД, у назві якої є `test`.
